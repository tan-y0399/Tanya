## 1 引言

### 1.1 编写目的

说明本文档作用：明确系统建设目标、范围与功能需求，作为设计、开发、测试与验收的依据。

### 1.2 项目背景与目标

- **业务背景**：企业级数据中心运维场景（教育/医疗等行业简化场景）、Linux 生产节点、自然语言驱动运维等。
- **建设目标**：自然语言与 OS 的桥梁；基于 MCP 扩展运维工具；安全护栏（意图过滤、最小权限、全链路审计）；根因分析与可控执行。

### 1.3 术语与缩写

| 术语 | 含义 |
|------|------|
| MCP | Model Context Protocol，模型上下文协议 |
| Agent | 智能体，负责感知、推理、调度工具与安全校验 |
| 护栏 | 独立于 LLM 的安全控制与审批机制 |
| RBAC | 基于角色的访问控制 |

### 1.4 参考资料

- 第十五届「中国软件杯」大赛 A2 官方赛题说明  
- 出题方技术解读 / 队内需求纪要（如有）

## 2 总体描述

### 2.1 产品形态

- **架构**：B/S（说明前后端职责、是否分离部署）。
- **运行环境**：LoongArch + 麒麟高级服务器操作系统 V11；开发与演示是否支持 x86/容器等（如实描述）。

### 2.2 用户角色

| 角色 | 描述 | 主要诉求 |
|------|------|----------|
| 运维管理员 | 通过 Web 对话下发运维意图 | 高效、可解释、可审计 |
| 安全/审计员 | 查看日志与审批记录 | 合规、可追溯 |
| 系统部署人员 | 安装与配置 | 文档清晰、可重复部署 |

### 2.3 约束与假设

- **约束**：不得未授权修改关键系统配置；高危操作需人工确认；须满足大赛提交物要求等。
- **假设**：网络可达模型服务；目标主机已安装指定采集工具或可由 Agent 调用等。

- 静态规则：高危命令、敏感路径、危险参数模式。
