## 1 引言

### 1.1 编写目的

本文档旨在明确"面向麒麟操作系统的安全智能运维 Agent"系统的建设目标、业务范围与功能需求，作为后续设计、开发、测试与验收的统一依据。本文档面向全体项目组成员（产品、开发、测试、部署）及评审方。

### 1.2 项目背景与目标

- **业务背景**：企业级数据中心运维场景中，传统运维依赖人工巡检与脚本处理，存在日志碎片化难以关联、排障效率低、经验难以沉淀复用等问题。本系统聚焦教育/医疗等行业的简化数据中心场景，面向 Linux 生产节点（麒麟操作系统），通过自然语言驱动运维，降低运维门槛。
- **建设目标**：
  - 构建自然语言与 OS 操作之间的智能桥梁，实现"说人话、做运维"
  - 基于 MCP（Model Context Protocol）协议扩展运维工具生态，实现运维能力资产化
  - 建立独立于 LLM 的安全护栏体系：意图过滤、最小权限、全链路审计
  - 实现智能化根因分析与可控执行闭环

### 1.3 术语与缩写

| 术语 | 含义 |
|------|------|
| MCP | Model Context Protocol，模型上下文协议，标准化工具接入规范 |
| Agent | 智能体，负责感知环境、推理决策、调度工具与安全校验 |
| ReAct | Reasoning+Acting，一种交替推理与行动的 Agent 范式 |
| Plan-Execute | 先规划后执行的 Agent 范式 |
| 护栏 | 独立于 LLM 的安全控制与审批机制 |
| RBAC | 基于角色的访问控制 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| TraceId | 全链路追踪标识，贯穿单次请求的完整生命周期 |

## 2 总体描述

### 2.1 产品形态

- **架构模式**：B/S 架构，前后端分离部署
  - 前端：Vue 3 + TypeScript 单页应用，通过 HTTP/WebSocket 与后端通信
  - 后端：Python FastAPI 服务，负责会话管理、Agent 编排、安全控制与持久化
  - Agent 编排层：独立进程，负责 ReAct/Plan-Execute 推理调度
  - MCP Server 层：按域拆分的独立进程，通过 stdio/SSE 与 Agent 通信
- **运行环境**：
  - 目标平台：LoongArch + 麒麟高级服务器操作系统 V11
  - 开发阶段支持 x86/Linux、容器化部署
- **部署方式**：支持物理机/虚拟机直接部署，提供 Docker Compose 容器化方案

### 2.2 用户角色

| 角色 | 描述 | 主要诉求 |
|------|------|----------|
| 运维管理员 | 通过 Web 对话下发运维意图，查看系统状态 | 高效执行、可解释输出、可审计 |
| 安全/审计员 | 查看操作日志与审批记录 | 合规、可追溯、不可篡改 |
| 系统部署人员 | 安装、配置与维护系统 | 文档清晰、依赖明确、可重复部署 |

### 2.3 约束与假设

- **约束**：
  - 不得在未授权情况下修改系统关键配置文件
  - 高危操作（格式化、批量删除、核心配置变更）必须经人工确认
  - 系统运行账户默认非 root
  - 须满足大赛初赛全部 9 项提交物要求
- **假设**：
  - 网络可达大模型 API 服务（本地部署或云端）
  - 目标管理主机已安装基础系统工具（lsof、netstat、journalctl 等）
  - Agent 执行账户已配置必要的 sudo 策略

## 3 功能需求

### 3.1 自然语言交互与任务理解 [FR-1xx]

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-101 | 多轮对话 | 支持维护会话上下文，记住前序操作结果与用户偏好 | 高 |
| FR-102 | 任务类型识别 | 自动分类用户意图：巡检、排障、清理、查询、配置等 | 高 |
| FR-103 | 模糊意图澄清 | 用户输入不明确时主动追问，确认目标主机、操作范围等 | 高 |
| FR-104 | 流式输出 | 模型推理与工具执行结果以流式推送到前端 | 中 |
| FR-105 | 会话历史 | 支持查看、检索历史会话记录 | 中 |

**验收要点**：用户可通过自然语言完成一次完整运维操作（如"查一下这台机器的磁盘使用情况"），Agent 正确理解意图并返回结构化结果。

### 3.2 OS 环境深度感知 [FR-2xx]

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-201 | 系统信息采集 | 采集 CPU、内存、磁盘、网络接口等基础指标 | 高 |
| FR-202 | 进程信息感知 | 调用 ps/lsof 等获取进程列表、端口占用、文件句柄 | 高 |
| FR-203 | 网络状态感知 | 采集网络连接、防火墙规则、路由表信息 | 高 |
| FR-204 | 日志采集分析 | 调用 journalctl 等读取系统日志，支持按时间/服务过滤 | 高 |
| FR-205 | 服务状态感知 | 查询 systemd 服务运行状态、自启配置 | 中 |
| FR-206 | 结构化快照 | 将采集数据统一为结构化 JSON 快照，供决策层消费 | 高 |
| FR-207 | 采集策略配置 | 采集规则可配置（YAML），支持频率控制与去抖 | 中 |
| FR-208 | 异常驱动采集 | 检测到异常指标时自动增加相关维度采集密度 | 低 |

**验收要点**：Agent 在某项运维任务前能自动获取相关系统状态，无需人工手动提供上下文。

### 3.3 MCP 运维工具插件 [FR-3xx]

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-301 | 工具注册与发现 | MCP Server 启动时自动注册工具列表，Agent 动态发现 | 高 |
| FR-302 | 基础查询工具 | 提供 get_cpu_info、get_memory_info、get_disk_usage 等只读工具 | 高 |
| FR-303 | 日志查询工具 | 提供 search_journal_logs 工具，支持参数化过滤 | 高 |
| FR-304 | 进程管理工具 | 提供 list_processes、get_process_detail 工具 | 高 |
| FR-305 | 服务管理工具 | 提供 get_service_status、restart_service 等工具 | 中 |
| FR-306 | 文件清理工具 | 提供 clean_temp_files、clean_old_logs 等工具（带安全检查） | 中 |
| FR-307 | 工具元数据规范 | 每个工具声明：入参Schema、出参Schema、readOnly/mutating、风险等级 | 高 |
| FR-308 | 工具超时与取消 | 每个工具设置超时时间，支持上层取消信号 | 高 |

**验收要点**：Agent 可通过 MCP 协议调用工具完成一次磁盘清理操作，工具执行结果正确返回且含风险标注。

### 3.4 安全意图校验 [FR-4xx]

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-401 | 静态规则过滤 | 维护高危命令/路径/参数模式规则库，命中即拦截 | 高 |
| FR-402 | 动态意图对齐 | 校验 Agent 拟执行动作是否与用户原始意图一致 | 高 |
| FR-403 | 风险分级 | 对操作进行 L1-L4 风险分级：只读/可逆/不可逆/关键变更 | 高 |
| FR-404 | 人工审批流程 | 高风险操作触发审批弹窗，运维管理员确认后执行 | 高 |
| FR-405 | 审批超时机制 | 审批请求设置超时，超时自动拒绝 | 中 |
| FR-406 | 规则库管理 | 支持通过配置文件/管理界面维护安全规则 | 中 |

**验收要点**：当用户要求执行 `rm -rf /etc/xxx` 时，安全护栏拦截并提示风险；当 Agent 意图偏离用户指令时触发告警。

### 3.5 最小权限代理执行 [FR-5xx]

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-501 | 非 root 运行 | 核心进程以普通用户运行，仅授权操作通过 sudo 提权 | 高 |
| FR-502 | 命令白名单 | 配置可执行命令白名单，白名单外命令拒绝执行 | 高 |
| FR-503 | 参数校验 | 对工具入参做类型、范围、格式校验，防注入 | 高 |
| FR-504 | 路径规范化 | 解析并规范化所有文件路径，防止 ../ 穿越 | 高 |
| FR-505 | 执行前备份 | 对写操作执行前自动备份关键配置（可选策略） | 中 |

**验收要点**：Agent 执行账户无法直接修改 /etc/passwd，需经 sudo 策略 + 审批方可执行。

### 3.6 推理链路溯源与审计 [FR-6xx]

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-601 | 全链路 TraceId | 每次请求生成唯一 TraceId，贯穿所有模块 | 高 |
| FR-602 | 审计日志记录 | 记录：时间、TraceId、用户、感知快照摘要、模型推理摘要、校验结果、执行命令、退出码、审批人 | 高 |
| FR-603 | 日志持久化 | 审计日志独立存储，仅追加不修改，支持导出 | 高 |
| FR-604 | 审计查询 | 按时间范围、用户、操作类型等条件检索审计日志 | 中 |
| FR-605 | 执行回放 | 基于审计日志可视化回放单次操作的完整链路 | 低 |

**验收要点**：任意一次操作均可通过 TraceId 追溯完整执行链路，包括决策理由与安全校验结果。

### 3.7 智能化根因分析 [FR-7xx]

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-701 | 告警解析 | 接收系统告警，自动启动分析流程 | 中 |
| FR-702 | 多源关联分析 | 关联指标、日志、进程等多维数据定位根因 | 中 |
| FR-703 | RAG 知识检索 | 检索运维知识库匹配历史案例和处置方案 | 中 |
| FR-704 | 分级处置建议 | L1 自动处置 / L2 知识库匹配 / L3 人机协同 | 中 |
| FR-705 | 方案安全校验 | 对生成的处置方案进行安全评估后执行 | 高 |

**验收要点**：给定一个模拟故障场景（如磁盘 I/O 飙升），Agent 能自动采集关联数据、定位根因并生成处置建议。

### 3.8 系统管理 [FR-8xx]

|------|------|------|--------|
| FR-801 | 用户认证 | 支持用户名/密码登录 | 中 |
| FR-802 | 模型配置 | 配置模型 API 地址、密钥、参数 | 中 |
| FR-803 | 工具开关 | 启用/禁用特定 MCP 工具 | 低 |

## 4 非功能需求

### 4.1 安全性

- 抗 Prompt 注入：输入层与模型输出层分别做策略校验，系统 Prompt 与用户内容分隔存储
- 敏感信息脱敏：日志中禁止打印完整密钥、口令、证书私钥
- 传输加密：HTTPS/TLS 保护前后端及模型 API 通信
- 护栏独立性：安全控制逻辑独立于 LLM，不依赖模型"自觉"

### 4.2 性能

- 典型对话响应时间：< 5 秒（含一次工具调用）
- 复杂任务响应时间：< 30 秒（含多次工具调用与推理）
- 工具并发数：单 Agent 实例支持同时 3 个工具并行调用
- 采集超时：单次系统采集 < 10 秒

### 4.3 可靠性

- 模型调用失败自动重试（最多 3 次，指数退避）
- 工具执行超时自动熔断
- 会话状态支持断点续跑
- 异常时返回明确错误信息而非静默失败

### 4.4 兼容性

- 浏览器：Chrome/Firefox/Edge 最近 2 个大版本
- 系统兼容：麒麟高级服务器操作系统 V11（LoongArch）
- 开发兼容：x86/Linux 可运行开发调试版本

### 4.5 可维护性

- 配置外置：所有配置通过 YAML 文件 + 环境变量管理
- 日志级别动态可调：ERROR / WARN / INFO / DEBUG
- 健康检查：各组件暴露 /health 接口
- 模块化架构：前端/后端/Agent/MCP Server 独立部署升级

## 6 外部接口需求

### 6.1 大模型 API

- 协议：OpenAI-compatible Chat Completions API
- 鉴权：API Key（Bearer Token）
- 支持流式（SSE）与非流式
- 支持 Function Calling / Tool Use

### 6.2 MCP 协议

- 传输方式：stdio（本地 MCP Server）或 SSE（远程/独立进程）
- 工具描述：JSON Schema 格式
- 版本：MCP 协议最新稳定版

### 6.3 前端-后端通信

- REST API：JSON over HTTPS
- WebSocket：用于工具执行结果实时推送（可选）
