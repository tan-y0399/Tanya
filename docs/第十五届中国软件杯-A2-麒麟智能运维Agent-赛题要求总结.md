# 第十五届「中国软件杯」A2 赛题要求总结（直播解读 + 官方说明 + 创新性要点）

> 赛题全称：**面向麒麟操作系统的安全智能运维 Agent 设计与实现**  
> 信息来源：大赛官网赛题页、麒麟软件技术直播/PPT、出题方答疑口径（以下分点按讲解逻辑组织，便于对照作品设计）。

---

## 一、赛题初衷与业务场景（为什么要做）

- **传统运维痛点**
  - 海量日志、复杂进程关系、多变配置，人工与脚本门槛高，易出错。
  - 监控多停留在「告警」，缺少自动跟进分析、根因定位与可执行修复方案；日志碎片化，难快速转化为决策。
- **赛题目标**
  - 利用大模型**自然语言理解 + 推理**，让 Agent 具备**感知、推理、执行**闭环能力。
  - 将运维经验**封装为可复用能力**；支持**告警解析、根因定位、修复方案生成**；作为**人与操作系统之间的交互桥梁**。
  - 向**主动巡检、潜在风险识别**演进；知识**沉淀到系统**、全领域复用；缩短故障平均处理时间（直播/PPT 中给出传统 vs 智能的耗时对比作为价值叙事）。
- **典型落地场景（讲解强调）**
  - 例：**清理系统垃圾**——传统脚本可能误删关键库日志导致崩溃；智能体应先**环境感知** → **文件/对象识别（可清理 vs 受保护）** → **安全校验（权限/风险）** → **按白名单/策略执行** → **全链路留痕与事后核验**，兼顾效率与稳定性。

---

## 二、官方「五大功能支柱」（及格线 / 必做能力）

1. **OS 环境深度感知**  
   - 自动调用底层工具（如 `lsof`、`netstat`、`journalctl` 等）获取进程、网络、日志等**实时上下文**；可扩展到指标、配置、链路等多模态数据。

2. **MCP 运维插件化**  
   - 参考 **MCP（Model Context Protocol）** 将清理、重启、配置变更等运维动作封装为**标准 Tools**，支持能力扩展与底层解耦，推动运维经验**资产化沉淀**。

3. **安全意图校验器**  
   - 对 LLM 原始输出做**二次过滤**（规则库 / 风险识别模型）；识别高危参数与危险操作模式；**高风险应触发人工审批/确认**。

4. **最小权限代理执行**  
   - 权限隔离；核心动作在**受限账号**下执行，**非必要不使用 root**；执行边界可控。

5. **推理链路溯源**  
   - 完整记录 **接收指令 → 感知环境 → 推理决策 → 安全校验 → 执行结果** 的闭环，支持异常回溯与审计。

---

## 三、非功能与安全「硬约束」（扣分红线 / 质量分水岭）

- **确定性**：严禁在未授权情况下修改**系统关键配置文件**（官网非功能需求）。
- **抗注入**：识别 **Prompt 注入**，防止对话诱导越权执行或泄露敏感信息（直播强调可做对抗用例自证）。
- **护栏独立性**：安全控制逻辑应**独立于 LLM**（直播/PPT：避免把「安全」完全交给模型「自觉」）。

---

## 四、推荐总体架构：「感知—决策—护栏」三层协同（讲解核心框架）

### 4.1 多维感知层（“眼睛”）

- **定位**：全量运维数据入口与事实基座；采集性能指标、告警、日志、链路、配置变更等。
- **能力建议（分档参考，来自直播/PPT）**
  - **初级**：基础采集 + 非结构化数据处理 + 关键词检索。
  - **进阶**：多源关联、实时计算、**预定义异常模式识别**。
  - **优秀/创新**：**预测性感知**（基于历史趋势输出风险预判与报告）。
- **工程化建议**：采集规则可配置（YAML/UI）；兼容 **OpenTelemetry / Prometheus** 等生态；形成「采集—清洗—结构化快照—知识索引—供决策层调用」的数据链。

### 4.2 推理决策层（“大脑”）

- **范式 A：ReAct（Thought → Act → Observation）**  
  - 适合交互强、环境不确定、需要步步修正的任务（告警查询、简单排障、探索式诊断）。
- **范式 B：Plan-Execute（先规划后执行，可重规划）**  
  - 适合多步骤复杂任务（性能瓶颈分析、跨组件故障、批量运维、强审计场景）；更利于**执行前全局审计**。
- **混合策略（讲解明确鼓励）**  
  - **Plan-Execute 做全局拆解与规划** + **ReAct 做子任务局部灵活执行** → 「全局可控 + 局部灵活」。
- **工具/MCP 要求（评分重点之一）**  
  - 工具设计遵循**单一职责**；覆盖指标查询、日志分析、故障处置、资源调度等核心路径；支持并行/嵌套调用；工具调用可审计、可扩展。

### 4.3 安全控制层（“护栏”）

- **双层防御（讲解/PPT）**
  - **静态规则过滤（前置拦截）**：敏感命令/高危关键词/高危等级操作库；命中即拦截并记审计日志。
  - **动态意图对齐（二次校验）**：校验模型拟执行动作是否与用户原始意图一致，防止「用户要 A、模型做 B」的偏离；高风险走**人工确认**。
- **行业级扩展能力（加分方向）**  
  - 风险分级与差异化审批；全链路审计与回放；**可回滚**（执行前备份/预案）；**沙箱预演**后再落生产。

### 4.4 多层级安全体系（PPT 给出的实现拆解参考）

- **静态风险评估**：规则引擎 + 风险分级（只读 / 可逆 / 不可逆 / 关键变更等）；对格式化磁盘、批量删除、核心配置变更等强拦截；支持自定义规则库。
- **动态意图审计**：交叉验证、对抗幻觉导致的指令偏离；工具幂等、指令全量日志、可追溯回放。
- **受限执行环境**：RBAC 最小权限；沙箱/容器隔离执行；关键变更前自动备份与一键回滚。

## 五、智能化根因分析与推理溯源（功能完整性中的高分项）

- **指标—日志关联分析**：跨数据源联动；例如磁盘 I/O 饱和时自动调用 `iotop` 等工具定位具体进程（讲解/PPT 示例）。
- **典型分析链路（讲解流程）**  
  异常触发 → 多维采集 → 推理关联 → **RAG 检索运维知识** → **关联历史相似案例** → 输出根因与处置方案 → **安全层校验方案风险** → 执行并记录全链路日志。
- **分级处置（L1–L3，讲解参考）**  
  - L1：已知问题规则化自动处置  
  - L2：复杂问题多源知识库检索匹配  
  - L3：未知/疑难触发人机协同
- **效果叙事参考（非强制数值，来自 PPT 表述）**  
  - 根因定位准确率、定位耗时从小时级压缩到分钟级等，可作为自测目标与报告亮点（需用真实测试数据支撑）。

## 六、运行环境、模型与工程实现（官方 + 答疑口径）

- **运行环境（官网硬条件）**  
  - **B/S 架构**；需能在 **LoongArch + 麒麟高级服务器版 V11** 环境部署运行。  
  - 开发阶段：**本地 / 虚拟机 / 云端**均可；与传统 Linux 运维命令体系一致（直播答疑）。环境镜像可从**麒麟官网**获取（具体链接以 QQ 群/官方通知为准）。
- **大模型（直播答疑）**  
  - **不限制**本地或云端调用方式；自研/微调模型可作为**加分展示项**。
- **框架（直播答疑）**  
  - **不限制** LangChain、LangGraph、Spring AI Alibaba、自研编排等；甚至可不用框架直接调用模型 API（但需保证工程可维护性与可演示性）。

## 八、评分导向（讲解/PPT 与官网的合并理解）

- **功能完整性（最大头）**：OS 感知与 MCP 插件、自然语言交互准确性、**安全护栏与风险控制**、**智能化根因分析**。  
- **创新与实用性**：差异化决策路径、混合架构、预测性运维、沙箱/回滚、对抗测试与安全证明等。  
- **文档与演示**：把「可审计、可复现、可部署」讲清楚。

---

## 九、避坑清单（直播强调的失分点）

- **不要过度依赖模型现生成 Shell/脚本**：确定性指标采集优先走**封装工具/MCP**；未经校验代码禁止直接执行。
- **必须建设注入防护与对抗验证**：如「忽略规则」「诱导泄露 `/etc/passwd`」等用例。
- **工程化稳定性**：长对话上下文、会话保活、任务状态持久化/断点续跑、全链路 TraceId、排障可观测性。
- **关键运维动作的人机协同**：人工确认、轮次上限、完成条件、异常重试、主备模型降级、执行后校验与回滚。

## 十、创新性：建议作为「亮点章节」写入设计文档的要点

下列内容在官网「基础要求」之上，来自直播/PPT 的明确加分叙事，可作为创新点选题与验证设计：

1. **混合推理架构创新**  
   - Plan-Execute 全局规划 + ReAct 局部执行；对不同类型工单自动路由决策范式。

2. **安全护栏工程化创新**  
   - 独立 **SecurityController / 审计 Agent（小模型）** 做二次意图对齐；风险分级审批工作流；执行前沙箱预演与自动回滚闭环。

3. **感知层智能化创新**  
   - 从「采集」升级到「结构化快照 + 知识关联」再到「预测性风险报告」；异常驱动的自适应采集策略。

4. **根因分析产品化创新**  
   - 指标/日志/追踪（Tracing）多源关联；RAG + 历史工单/案例库；L1–L3 分级处置与人机协同界面。

5. **可观测与合规创新**  
   - CoT/工具参数/审批记录/执行结果四元绑定；支持审计回放与责任边界证明（满足生产级 Agent 的可观测要求）。

6. **工具生态与 MCP 资产化**  
   - 工具颗粒度与组合编排（并行/嵌套）、可注册可治理的工具目录；把「运维 SOP」沉淀为可版本化的工具与策略包。

## 十一、给初学者的最小学习路径（直播建议压缩版）

- **智能体基础**：模型如何调用工具、工具返回如何进入上下文、如何驱动下一步推理。  
- **工具与 MCP**：先做出可用 Demo，再扩展工具覆盖面与治理能力。  
- **安全与审计**：理解「为什么不能把机器完全交给模型」；把校验、权限、留痕做成默认路径而非附加项。
